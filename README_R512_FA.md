# سفارش ترکیبی و بررسی شرکت — 5.4.3.3-r5.12

مبنای سورس با انتخاب مالک: `mahantah/ghadirpartner-android-r2`، کامیت
`fab0a415c47bda76b47c7bfd9d81a29eb1d4ebce` (R5.6).
فایل‌های نصب R5.11 در مخزن `curser` منبع Kotlin یا کلید امضا ندارند؛ این تغییر ادعای بازسازی سورس آن بسته‌ها را ندارد.

- یک مدل با چند نوع قیمت در سبد قابل خرید است. افزودن دوبارهٔ همان نوع خرید تعداد را جمع می‌کند؛ حذف یک نوع، نوع دیگر را حذف نمی‌کند.
- موجودی بر اساس مجموع تعداد مدل کنترل می‌شود؛ افزایش تعداد سریال آزاد از مرز تعرفه، قیمت تمام سریال‌های همان مدل را به‌روز می‌کند.
- روش تسویهٔ کل سفارش، برای پنل و سریال آزاد، نقد / چک / اعتباری است. روش تسویه، کلید قیمت کاتالوگ را جعل یا تغییر نمی‌دهد.
- فاکتور رسمی/غیررسمی بدون پیش‌انتخاب، اجباری و همیشه نمایان است.
- متن تعهد اعتباری زیر انتخاب روش و در مرحلهٔ تسویه نمایش داده می‌شود. بدون تیک نمی‌توان ثبت کرد؛ تغییر سبد یا روش، تأیید قبلی را پاک می‌کند.
- مراحل مشتری شامل بررسی شرکت است؛ رد شرکت با علت دیده می‌شود. نقش‌های فروش/ادمین در اتوماسیون دکمهٔ تأیید/عدم تأیید دارند. تأیید شرکت مجوز پرداخت یا ارسال نیست.
- قیمت‌های مستقل از `purchase_items` در جزئیات و PDF خوانده می‌شوند؛ `items` برای انبار یک قلم فیزیکی به ازای مدل نگه می‌دارد.

وابستگی سرور: بستهٔ `native-order-flow` در مخزن وب باید پیش از توزیع اپ نصب و بررسی شود. سرور قدیمی خرید ترکیبی و اعتبار را رد می‌کند. هیچ سفارش آزمایشی زنده ارسال نشود.

تنظیمات نسخه، سقف تعداد، مرز تعرفه و متن تعهد: `config/order-flow.yaml`؛ Gradle ساختار و محدوده‌ها را اعتبارسنجی می‌کند.

بررسی پروژه:

```sh
gradle --no-daemon --console=plain :app:testPortalDebugUnitTest :app:assemblePortalDebug :app:assemblePortalDebugAndroidTest :app:lintPortalDebug :app:assembleAutomationDebug :app:lintAutomationDebug
bash validation/run-emulator-tests.sh
```

خروجی CI از نوع debug با شناسهٔ جداگانه است و جایگزین اپ انتشار نمی‌شود. مخزن فعلی ساخت release یا ارجاع به کلید انتشار ندارد؛ کلید خصوصی نباید به این مخزن عمومی اضافه شود. امضای نهایی باید با همان کلید R5.11 در محیط امن ساخت مالک انجام شود.
